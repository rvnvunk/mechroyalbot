# Mech Royale 봇 프로젝트 가이드 (Builders Buildathon · Builders 트랙)

> 출처: https://www.joinbuilders.org/buildathon/tracks/builders (2026-11-22 기준 정리)
> **마감: 월요일 오전 1:00 (KST, GMT+9)**
> 상금 $5,000 · 참가 팀 약 360팀

---

## 1. 과제 한 줄 요약

16대의 메크가 싸우는 3D 배틀로얄(OSU 캠퍼스 맵)에서 **내 메크를 조종하는 AI 봇 코드**를 만든다.
**마지막까지 살아남을수록 점수가 높다.** 킬 수는 점수에 안 들어간다.

---

## 2. 게임 규칙

- 16대가 OSU Oval에 떨어짐. 건물, 옥상, 나무 등 엄폐물 있음
- 약 **7분** 동안 자기장(zone)이 점점 좁혀짐
- 시작 무기: **arm gun (팔 총)**
- 경기 중 줍는 무기: **mortar(박격포), charged laser(충전 레이저), lightning(번개)**
- **power cube**: 킬하거나 상자(crate)에서 얻음 → 업그레이드 구매에 사용
- **순위만 중요**: 5킬 하고 1등으로 죽는 것 < 0킬로 끝까지 생존
- 브라우저에서 직접 플레이 가능: https://play.joinbuilders.org
- 채점 경기는 봇끼리만 함

---

## 3. 봇 인터페이스

| 항목 | 내용 |
|---|---|
| 통신 방식 | stdin / stdout 으로 `mechfight/1` JSON 라인 주고받기 (자세한 건 `protocol.md`) |
| 주기 | 초당 10번 관측(observation) 받음 (보이는 것, 들리는 것) |
| 응답 내용 | 어디로 이동, 어디 조준, 발사 여부 |
| 응답 제한 시간 | **관측당 50ms** |
| 늦은 응답 | 무시됨 → 1초간 마지막 이동/조준 유지하고 발사 안 함 → 그 후 정지 |

> 응답 시간은 실행마다 몇 ms씩 달라짐. 50ms에 아슬아슬하면 재실행 시 점수가 달라질 수 있으니 **여유 있게 (예: 20~30ms 이내)** 응답하도록 만들 것.

## 4. 실행 환경 제한

### 빌드 시
- linux/amd64
- 네트워크 사용 가능
- 최대 **10분** 안에 빌드 끝나야 함
- **버전 고정(pin) 필수** (결선 진출 시 다시 빌드함)
- 언어, 라이브러리, AI 사용 모두 자유

### 실행 시 (런타임)
- CPU **1개**, 메모리 **512MB**
- 맵 파일: `/arena` (읽기 전용)
- **네트워크 없음**
- **root 아님** (uid 65534로 실행 → 패키지는 시스템 전체에 설치해야 함)
- 디스크 쓰기는 `/tmp` 만 가능 (최대 64MB)

### 저장소
- 제출 커밋 기준 **20MB 이하**
- **Dockerfile이 저장소 최상단(root)에 있어야 함**
- 제출할 때 **public** 이어야 함 (채점 끝나면 private로 바꿔도 됨, 주최측이 복사본 보관)

## 5. 시작 3단계

1. `mechfight-kit.tar.gz` 다운로드 → **Python 또는 TypeScript 폴더**를 public GitHub 저장소 최상단에 복사 (Dockerfile이 맨 위에 오게)
2. 이미지 빌드 후 `check/check.py` 로 테스트 (명령어는 킷의 README 참고)
3. push 후 제출 페이지에 저장소 URL 제출

### 킷에 들어있는 것
- Python / TypeScript 스타터 봇
- 래퍼(wrapper), Dockerfile
- `protocol.md` (전체 규칙서: 맵, 무기, 관측, 행동, 프로토콜)
- JSON Schema
- `check/check.py`
- 맵 파일

---

## 6. 점수 계산

- 한 경기 점수 = **16 − 순위** (1등 15점, 첫 번째로 죽으면 0점)
- 같은 틱(tick)에 죽으면 같은 순위
- 최종 점수 = 모든 경기 점수의 **평균**
- 동점이면 **먼저 제출한 팀**이 위
- 채점기 버전: `builders-3`

### 기준선과 현재 상위권
| 구분 | 점수 |
|---|---|
| 스타터 Python 봇 (넘어야 할 기준) | **1.15** |
| 현재 리더보드 1위권 | 약 **6.4 ~ 6.6** |
| 상위 32위 컷 (결선 예선 진출) | 약 **6.2** 정도 |

---

## 7. 연습(Practice) 채점 방식

- **48경기**, 상대는 하우스 봇 15대 (easy 4, medium 4, hard 4, expert 3)
- 하우스 봇들은 **한 팀처럼 행동**:
  - 시야 공유
  - 서로 안 싸움
  - **약한 것부터 사냥** → 처음엔 1대가, 숫자가 줄수록 더 많이, 후반엔 전부 나를 쫓아옴
- 시드는 비공개이고 대회 내내 고정. 봇은 시드를 모름. 내 슬롯과 스폰 위치는 매 경기 다름
- 빌드 실패 / check 실패 → 거절되고 이유 알려줌, 최고 점수엔 영향 없음
- 봇이 크래시하거나 응답 멈추면 → 거절 안 되고 **가만히 서 있는 과녁**으로 경기에 남아 채점됨
- 제출 횟수: **팀당 1시간에 4번** (거절된 제출도 1회로 카운트)
- 채점은 보통 몇 분 걸림

> 핵심: 실질적으로 **15대 팀 vs 나 1대**. 후반으로 갈수록 전부 나에게 몰려옴. 정면 싸움보다 **생존, 회피, 엄폐, 자기장 관리**가 중요.

---

## 8. 결선(Final) 방식

1. 마감 시점에 선택한 제출물(기본은 최고 점수)이 연습 점수와 함께 고정
2. **상위 32팀** → 예선: 각 16경기, 참가팀끼리 16인 개인전, 새 시드
3. 예선 평균 상위 **16팀** 진출 (점수 공개 없이 발표)
4. 16팀이 **64경기 시리즈** (마지막 4경기는 현장 라이브, 점수 동일하게 반영)
5. 시리즈 평균만으로 순위 결정, 동점은 먼저 제출한 팀 우선
6. 결선에서 빌드 실패하면 0점 → **버전 고정 꼭 하기**

> 결선은 하우스 봇이 아니라 **다른 참가자 봇들**과 개인전. 연습 환경(15대 협공)에만 과하게 맞추면 결선에서 다를 수 있음.

## 9. 프로젝트 진행 계획 (추천)

### 단계 1. 환경 세팅 (30분)
- [ ] 킷 다운로드, Python 폴더를 새 public 저장소 최상단에 복사
- [ ] Docker 빌드 → `check/check.py` 통과 확인
- [ ] 스타터 봇 그대로 한 번 제출해서 파이프라인 확인 (점수 약 1.15 나와야 정상)

### 단계 2. 프로토콜 이해 (30분~1시간)
- [ ] `protocol.md` 정독: 관측 필드(내 위치, HP, 적 위치, 소리, 자기장, 아이템), 행동 필드(move, aim, fire, 무기 선택, 업그레이드)
- [ ] 맵 파일(`/arena`) 구조 파악: 건물, 엄폐물 위치

### 단계 3. 생존 우선 봇 (가장 효과 큼)
- [ ] **자기장 안쪽 유지**: 자기장 중심 쪽으로 미리 이동
- [ ] **적과 거리 유지**: 적이 보이면 반대 방향 + 엄폐물 뒤로
- [ ] **엄폐물 활용**: 건물/나무로 시야 차단
- [ ] 체력 낮으면 무조건 도망 모드

### 단계 4. 전투 보강
- [ ] 가까이 온 적만 공격 (조준 시 이동 예측)
- [ ] 무기 픽업 / power cube 로 업그레이드 (방어, 체력 쪽 우선 고려)
- [ ] 무기별 사거리에 맞는 거리 유지

### 단계 5. 안정성
- [ ] 응답 시간 측정 → 평균 20~30ms 이하 유지
- [ ] 예외 처리: 어떤 입력에도 크래시 안 나게 (크래시 = 서 있는 과녁)
- [ ] 메모리 512MB, CPU 1개 안에서 동작 확인

### 단계 6. 반복 개선
- 1시간에 4번 제출 가능 → 변경 하나씩 넣고 점수 비교
- 마감 직전엔 가장 점수 높고 안정적인 버전 선택
